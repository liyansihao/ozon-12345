## 六个问题的答案

### 1. 哪些来源大量产生 non-pure-fbs？

- “白蓝花盆”搜索：11/12。
- Wizzal 两个价带合计：15/18。
- Upcloud 三个价带合计：13/19。
- “金属收藏模型”搜索：7/16。

四组贡献了 46/48 次 non-pure-fbs。

### 2. 哪些来源 pure FBS 比例最高？

有意义样本中 Kids Wheels 为 8/8；Nature 为 4/6；“金属收藏模型”搜索为 9/16。历史上 Fluff Joy base 11/11、Breezelife 12/13，但它们的 1688/最终转化差，不能只凭 pure FBS 率优先。

### 3. 哪些类目最容易找到可靠的 1688 同品？

当前高可信细分是标准化模型车（Wizzal pure-FBS 子集 3/3）和 Nature 当前样本（4/4）；历史 `plush` 为 5/5，但利润通过仅 2/5。`building` 只有 1/9，应该降权。

### 4. 哪些来源历史最终上架率最高？

Kids Wheels 25%、Wizzal base 20%、Wizzal ¥500 12.5%、Upcloud ¥500 10%、Miaowu 9.1%。小样本必须使用置信度收缩，不能把 1/1 当作 100% 稳定来源。

### 5. 当前 source 调度是否重复消费低产来源？

是。调度排序使用的 `sourceYieldKey` 会合并 `sorting/page`，但运行时 low-FBS 采样熔断使用完整 URL。相同 seller/search 换 `sorting` 或 `page` 后会重新获得 3/8 个详情采样预算：

- Wizzal base、rating、discount、page=2 被分别采样。
- Upcloud base、rating、discount 和两个价带被分别采样。
- “白蓝花盆” page 1/2 被分别采样。
- “金属收藏模型”多个 sorting/page 被分别采样。

这解释了已经出现连续 non-pure 之后仍继续打开同族详情。

### 6. 为什么 v100 仍让 48 个非纯 FBS 商品进入昂贵流程？

v100 设置 `FLOW_B_VERIFY_LISTING_FBS_DETAIL=1`，符合“最终必须真实详情验证”。48 个最终 non-pure 商品的列表卡证据为：

- 明确 FBS：6；
- `暂无数据`：29；
- 缺失：6；
- `--`：5；
- 明确 FBO：2。

只有 6/48 在卡片上明确显示 FBS，42/48 是不确定证据；现有逻辑为了不把推断当真，会打开详情确认。问题不在“详情验证太严格”，而在：

1. 不确定卡片没有结合完整来源漏斗排序；
2. low-FBS 熔断按完整 URL 分裂，排序/翻页会重置样本；
3. 当前 `fullFunnelSourceScores` 把 favorited、submitted、published 加权相加，没有单独记录 1688 可靠率、利润通过率、最终率、样本置信度、近期失败串和证据时效。

## 第一轮建议变量

第一轮只替换来源评分定义，不改变 Ozon 15 秒间隔、不提前认定 pure FBS、不改变 1688/P70/利润/最终确认规则：

- 按 `sourceYieldKey` 聚合排序和翻页变体，价格带仍分开。
- 记录 `pure_fbs_rate`、`reliable_1688_rate`、`profit_pass_rate`、`final_publish_rate`、`sample_size`、`recent_failure_streak`、`last_success_at`。
- 使用 v100 全局阶段率 39.2% / 48.3% / 71.4% / 60.0% 作为经验先验，对小样本做收缩。
- 排序目标是每个 Ozon 详情 slot 的预期最终成功率；近期连续失败和过旧证据降低置信度。
- 仍保留探索配额；低分来源不被标记为 non-FBS，只是排在已验证高完整漏斗来源之后。

如果这一单变量在 10 分钟小样中不能显著降低 60.8% non-pure 或提高 48.3% 可靠成本率，则撤销评分修改；下一轮才单独处理 low-FBS 熔断键，不能两项同时上线。

## 第一轮实现与离线排序预检

第一轮只改了 `fullFunnelSourceScores` 的评分定义：

- 同一 source/SKU 的多阶段事件合并为一条漏斗事实，sorting/page 变体通过 `sourceYieldKey` 聚合，价格带继续隔离。
- 每个来源记录样本数、六个阶段计数和条件转化率、近期连续失败数、最后成功/事件时间及置信度。
- 使用 v100 阶段率作为经验先验；样本量和证据时效影响置信度。
- 最终确认是核心结果；尚未最终确认的 submission 只按 0.25 的领先信号计入，不能替代最终成功。
