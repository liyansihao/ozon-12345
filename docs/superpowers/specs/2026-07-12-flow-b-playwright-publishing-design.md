# Flow B Playwright 上架流程设计

## 目标

将 Flow B 的浏览器扫描、毛子 ERP 收藏夹处理、利润计算和真实上架统一到 Playwright 持久化浏览器中，移除 AppleScript 和重复浏览器入口。流程持续处理候选商品，直到成功上架 100 个最终利润率严格大于 30% 的商品。

所有合格商品发布到名称匹配“丽丽1号”的店铺，并使用名称匹配 `lysh` 的水印。

## 范围

本次改造包含：

- 使用 Playwright 的 Chrome for Testing 和持久化 profile 复用 Ozon、毛子 ERP 登录态。
- 自动加载本地毛子 ERP 浏览器插件。
- 扫描 Ozon 卖家页并向毛子收藏夹补充候选商品。
- 分页读取毛子收藏夹并去除已发布 SKU。
- 获取商品详情、发货模式、价格、类目、佣金、尺寸、重量和图片。
- 调用保留的 Python 1688 成本模块估算采购成本。
- 使用毛子 ERP 的 CEL Economy 结果计算最终利润率。
- 严格筛选最终利润率大于 30% 的商品。
- 将合格商品直接提交到指定店铺和水印，直到明确成功 100 个。
- 保存每个 SKU 的状态和证据，支持中断恢复。
- 删除被 Playwright 版本替代的 AppleScript、重复扫描器、旧上架器和临时桥接文件。

本次不重写成熟的 1688 图搜、成本匹配和成本可靠性算法，也不删除历史运行数据、发布记录或用户业务数据。

## 架构

保留 `flow_b_playwright.mjs` 作为唯一浏览器命令入口，支持以下子命令：

- `setup`：启动带毛子插件的 Chrome for Testing，供用户完成登录。
- `scan`：扫描 Ozon 来源并补充毛子收藏夹。
- `publish`：处理已有收藏，计算利润并真实上架。
- `run`：串联扫描和上架，直到成功上架目标数量。

浏览器逻辑拆分为以下单一职责模块：

- `browser-context.mjs`：解析 profile、Chrome for Testing、插件路径，创建持久化 context，检查登录状态并管理页面。
- `maozi-client.mjs`：封装收藏夹、店铺、水印、商品详情、利润计算和上架请求。
- `publish-policy.mjs`：实现禁止类目、纯 FBS、成本可靠性、佣金完整性和严格利润门槛判断。
- `publish-state.mjs`：原子写入进度、SKU 状态、成功记录和运行摘要。
- `publish-runner.mjs`：编排候选获取、成本、利润、发布、失败继续和目标计数。

Python 仅保留纯业务能力：

- `1688_image_median.py` 负责 1688 图搜和成本证据。
- 必要的成熟商品匹配及成本可靠性函数保留为可测试的纯逻辑模块。
- Node.js 与 Python 通过明确的 JSON 输入输出文件协作；Python 不再打开或控制浏览器。

## 店铺和水印解析

运行开始时从毛子 ERP 实时读取可用店铺和水印列表。

匹配规则：

1. 名称统一转为小写。
2. 去除空格、中英文标点和常见分隔符。
3. 店铺候选名称包含归一化后的“丽丽1号”即可匹配。
4. 水印候选名称包含归一化后的 `lysh` 即可匹配。
5. 如果有多个候选，使用接口列表中的第一个。
6. 将最终选择的名称和 ID 写入运行配置快照及每次发布记录。
7. 如果没有候选，停止运行，不提交任何商品。

## 数据流

### 1. 启动与恢复

运行创建独立目录并保存配置快照，其中包含 profile、插件版本、利润门槛、目标数量、店铺、水印、运行时间和输入来源。

启动时读取已有 SKU 状态：

- `published`：明确成功，永不重复提交。
- `skipped`：业务规则不合格，默认不重算。
- `failed`：本次运行记录失败后继续；恢复时允许重试，但必须在提交前再次查询是否已存在。
- `processing`：上次进程中断的商品，先查询远端状态，再决定标记成功或重试。

### 2. 候选读取

从毛子收藏夹分页读取候选，并排除全局发布记录及当前运行中的已完成 SKU。若收藏数量不足，`run` 子命令调用 `scan` 补充候选后继续。

### 3. 详情与前置过滤

获取 Ozon 和毛子商品信息，沿用现有规则跳过：

- 食品、饮料和宠物食品。
- 服装、时尚商品。
- 数码和 3C 商品。
- 液体、喷雾、粉末、胶水、油品、药品和保健品。
- 明显品牌或知识产权高风险商品。
- 人形模特、人体模型和解剖模型。
- FBO 或 FBO/FBS 混合发货商品；只允许纯 FBS。

售价使用 Ozon 当前售价与毛子跟卖最低价中的较低值。

### 4. 采购成本

将 SKU、商品标题、类目、型号、主图和期望信号写入 JSON，调用 Python 1688 模块。只有成本证据通过现有可靠性规则时才继续；无结果、弱匹配、异常价格簇或人工复核项均跳过。

### 5. 利润计算

使用毛子 ERP 接口计算 CEL Economy 物流方案。最终结果必须同时满足：

- 存在 CEL Economy 结果。
- `cate_rate > 0`。
- `cate_fee > 0`。
- 采购成本大于 0。
- 售价大于 0。
- 最终利润率严格大于 30；等于 30 不合格。

利润数据和计算证据在提交前写入 SKU 状态。

### 6. 上架

流程不提供 dry-run，不执行单品试运行。`publish` 或 `run` 子命令启动后，会对合格商品直接提交真实上架请求。

发布载荷固定使用本次解析出的“丽丽1号”店铺 ID 和 `lysh` 水印 ID。只有毛子接口返回明确成功且响应包含成功语义时，才计入成功数量并写入全局发布记录。

目标计数只统计本次运行中新确认成功的商品；达到 100 后立即停止继续取候选。

## 错误处理

单个商品发生以下情况时记录 `failed` 并继续下一个：

- 页面或接口超时。
- Ozon 风控或页面结构异常。
- 毛子接口错误。
- 1688 成本程序失败。
- 利润响应不完整。
- 上架结果不明确。

对于结果不明确的上架请求，状态记录请求摘要、响应摘要和时间。恢复时必须先查询远端是否已存在该 SKU；确认不存在后才允许重新提交。

以下全局错误会停止整批运行：

- Playwright profile 未登录。
- 毛子插件未加载。
- 店铺或水印找不到候选。
- profile 被其他进程锁定。
- 状态文件损坏且无法安全恢复。

## 状态与审计

每次运行保存：

- `run_config.json`：不可变运行配置快照。
- `sku_states.jsonl`：每个 SKU 的状态转换和原因。
- `published.jsonl`：明确成功的发布证据。
- `failed.jsonl`：失败请求及可恢复信息。
- `skipped.jsonl`：业务规则跳过原因。
- `summary.json`：候选数、成功数、失败数、跳过数和剩余目标。

写入使用临时文件加原子替换，防止中断产生半个 JSON。全局 `data/flow_b/published_links.csv` 继续作为跨运行去重来源，但新代码通过单一状态模块更新，避免多处追加逻辑。

## 清理策略

新入口通过自动测试和只读登录检查后，直接删除所有无引用的旧浏览器控制与重复入口，包括：

- `flow_b_chrome_js.py`
- `flow_b_chrome_js_tab.py`
- `flow_b_rescan_sources_deep.py`
- `flow_b_rescan_sources_multitab.py`
- `flow_b_scroll_sources.py`
- `flow_b_playwright_gap_browser.mjs`
- `flow_b_playwright_gap_scan.mjs`
- `flow_b_resume_gap_to_maozi.sh`
- `flow_b_retry_publish_payloads.py`
- 已被新模块覆盖的收藏夹注入和浏览器详情提取脚本
- 完成纯逻辑迁移后的 `flow_b_process_batch.py`

删除前必须用 `rg` 检查脚本、npm 命令、测试和文档引用，并同步修改仍有效的高产池入口。历史运行目录、历史生成的临时 JS、发布记录和数据文件不在清理范围内。

## 测试与验收

使用 Node.js 内置 `node:test` 编写新模块测试，保留与纯 Python 算法相关的现有测试。

必须覆盖：

- 利润率 30 不通过，30.01 通过。
- `cate_rate` 或 `cate_fee` 为 0 时禁止发布。
- 店铺和水印使用归一化包含匹配，并在多个候选时选择第一个。
- 找不到店铺或水印时整批停止。
- 已发布 SKU 不会再次进入发布队列。
- 单个失败会记录并继续处理下一个。
- 只有明确成功才增加成功计数。
- 达到 100 后立即停止。
- `processing` 状态恢复时先查询远端。
- 状态文件可在进程中断后恢复。
- 发布载荷固定使用解析出的店铺和水印 ID。

自动测试使用本地假接口或注入式 transport，不访问真实上架接口。浏览器级验证只执行：

- Chrome for Testing 可启动。
- 毛子 3.0.9 插件可加载。
- Playwright profile 登录态可读取。
- 店铺和水印候选可解析。
- 毛子收藏夹可读。

自动验证阶段不提交真实商品。真实发布仅由用户明确运行 `publish` 或 `run` 命令触发。

## 验收标准

- 项目只有一个受支持的浏览器自动化入口。
- 受支持入口不调用 `osascript`、AppleScript 或普通 Chrome 当前 Tab。
- 利润门槛在配置、代码、文档和测试中统一为严格大于 30%。
- 店铺和水印按确认的非精确规则解析并记录最终 ID。
- 失败商品不会阻塞整批流程。
- 重启后不会重复发布已成功商品。
- 成功计数达到 100 后停止。
- 被替代代码直接删除，历史数据完整保留。
- Node 和 Python 测试通过，且只读浏览器检查通过。
